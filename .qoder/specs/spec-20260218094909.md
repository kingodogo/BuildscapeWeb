# MongoDB to Supabase Migration Plan

## Overview
Migrate BuildscapeWeb from MongoDB Atlas to Supabase PostgreSQL, replace custom bcrypt auth with Supabase Auth, consolidate all serverless functions into Netlify, and implement Row Level Security (RLS).

**Deployment target:** Netlify only (Vercel has >12 function limit issues)
**Data migration:** Fresh start (no existing data to migrate)

---

## Prerequisites (Before Implementation)

1. Supabase credentials are in the `supabase` file at project root:
   - Project URL: `YOUR_SUPABASE_URL`
   - Public (anon) key: `YOUR_SUPABASE_ANON_KEY`
   - Secret (service_role) key: `YOUR_SUPABASE_SERVICE_ROLE_KEY`
2. **SECURITY:** Add `supabase` to `.gitignore` immediately (it contains secrets and is currently NOT ignored)
3. Install `@supabase/supabase-js` dependency
4. Remove `mongodb` and `bcryptjs` dependencies when migration is complete
5. **Login method:** Email + password (confirmed by user)

CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.profiles (id, username, email, role)
  VALUES (
    NEW.id,
    COALESCE(NEW.raw_user_meta_data->>'username', split_part(NEW.email, '@', 1)),
    NEW.email,
    COALESCE(NEW.raw_user_meta_data->>'role', 'user')
  );
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();

### 2.5 Row Level Security (RLS) Policies

```sql
-- Enable RLS on all tables
ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;
ALTER TABLE reports ENABLE ROW LEVEL SECURITY;
ALTER TABLE suggestions ENABLE ROW LEVEL SECURITY;
ALTER TABLE config ENABLE ROW LEVEL SECURITY;
ALTER TABLE changelogs ENABLE ROW LEVEL SECURITY;
ALTER TABLE wiki_features ENABLE ROW LEVEL SECURITY;
ALTER TABLE kofi_payments ENABLE ROW LEVEL SECURITY;
ALTER TABLE kofi_manual_rewards ENABLE ROW LEVEL SECURITY;
ALTER TABLE redeem_codes ENABLE ROW LEVEL SECURITY;
ALTER TABLE code_redemptions ENABLE ROW LEVEL SECURITY;
ALTER TABLE user_rewards ENABLE ROW LEVEL SECURITY;
ALTER TABLE minecraft_users ENABLE ROW LEVEL SECURITY;
ALTER TABLE cosmetics ENABLE ROW LEVEL SECURITY;
ALTER TABLE supporters ENABLE ROW LEVEL SECURITY;
ALTER TABLE connection_codes ENABLE ROW LEVEL SECURITY;
ALTER TABLE support_tiers ENABLE ROW LEVEL SECURITY;

-- Helper: check admin/owner role
CREATE OR REPLACE FUNCTION public.is_admin_or_owner()
RETURNS BOOLEAN AS $$
BEGIN
  RETURN EXISTS (
    SELECT 1 FROM profiles WHERE id = auth.uid() AND role IN ('admin', 'owner')
  );
END;
$$ LANGUAGE plpgsql SECURITY DEFINER STABLE;

-- PROFILES
CREATE POLICY "profiles_select" ON profiles FOR SELECT USING (true);
CREATE POLICY "profiles_update_own" ON profiles FOR UPDATE USING (auth.uid() = id);
CREATE POLICY "profiles_admin_update" ON profiles FOR UPDATE USING (is_admin_or_owner());
CREATE POLICY "profiles_admin_delete" ON profiles FOR DELETE USING (is_admin_or_owner());

-- PUBLIC READ tables (reports, suggestions, changelogs, wiki, config, cosmetics, support_tiers)
CREATE POLICY "reports_select" ON reports FOR SELECT USING (true);
CREATE POLICY "reports_insert" ON reports FOR INSERT WITH CHECK (auth.role() = 'authenticated');
CREATE POLICY "reports_update" ON reports FOR UPDATE USING (author_id = auth.uid() OR is_admin_or_owner());
CREATE POLICY "reports_delete" ON reports FOR DELETE USING (author_id = auth.uid() OR is_admin_or_owner());

CREATE POLICY "suggestions_select" ON suggestions FOR SELECT USING (true);
CREATE POLICY "suggestions_insert" ON suggestions FOR INSERT WITH CHECK (auth.role() = 'authenticated');
CREATE POLICY "suggestions_update" ON suggestions FOR UPDATE USING (author_id = auth.uid() OR is_admin_or_owner());
CREATE POLICY "suggestions_delete" ON suggestions FOR DELETE USING (author_id = auth.uid() OR is_admin_or_owner());

CREATE POLICY "config_select" ON config FOR SELECT USING (true);
CREATE POLICY "config_all_admin" ON config FOR ALL USING (is_admin_or_owner());

CREATE POLICY "changelogs_select" ON changelogs FOR SELECT USING (true);
CREATE POLICY "changelogs_all_admin" ON changelogs FOR ALL USING (is_admin_or_owner());

CREATE POLICY "wiki_select" ON wiki_features FOR SELECT USING (true);
CREATE POLICY "wiki_all_admin" ON wiki_features FOR ALL USING (is_admin_or_owner());

CREATE POLICY "cosmetics_select" ON cosmetics FOR SELECT USING (true);
CREATE POLICY "cosmetics_all_admin" ON cosmetics FOR ALL USING (is_admin_or_owner());

CREATE POLICY "support_tiers_select" ON support_tiers FOR SELECT USING (true);
CREATE POLICY "support_tiers_all_admin" ON support_tiers FOR ALL USING (is_admin_or_owner());

-- ADMIN-ONLY tables
CREATE POLICY "redeem_codes_admin" ON redeem_codes FOR ALL USING (is_admin_or_owner());
CREATE POLICY "code_redemptions_own" ON code_redemptions FOR SELECT USING (true);
CREATE POLICY "code_redemptions_admin" ON code_redemptions FOR ALL USING (is_admin_or_owner());

-- USER-SCOPED tables
CREATE POLICY "user_rewards_select" ON user_rewards FOR SELECT USING (true);
CREATE POLICY "kofi_payments_select" ON kofi_payments FOR SELECT USING (true);
CREATE POLICY "kofi_manual_rewards_select" ON kofi_manual_rewards FOR SELECT USING (true);
CREATE POLICY "kofi_manual_rewards_admin" ON kofi_manual_rewards FOR ALL USING (is_admin_or_owner());

-- SERVICE-ROLE-ONLY tables (Minecraft mod endpoints bypass RLS via service_role)
-- No anon/authenticated policies needed - server functions use supabaseAdmin
CREATE POLICY "minecraft_users_service" ON minecraft_users FOR ALL USING (false);
CREATE POLICY "supporters_service" ON supporters FOR ALL USING (false);
CREATE POLICY "connection_codes_service" ON connection_codes FOR ALL USING (false);
```

> **Note:** Tables accessed exclusively by Minecraft mod endpoints (`minecraft_users`, `supporters`, `connection_codes`) have `USING (false)` policies. The server-side `supabaseAdmin` client uses service_role which bypasses RLS entirely, while the frontend never touches these tables directly.

## Phase 3: Authentication Migration

### 3.1 Rewrite `services/auth.ts`
**Current:** All methods call `/api/auth` with action-based routing, stores raw user in localStorage
**New:** Use Supabase Auth SDK directly from browser for login/register/logout/password-reset. Keep Netlify function calls for server-side operations (Minecraft linking, admin ops).

Key changes:
- `login()` -> `supabase.auth.signInWithPassword({email, password})` + fetch profile from `profiles` table
- `register()` -> `supabase.auth.signUp({email, password, options: { data: { username }}})` + profile auto-created by trigger
- `logout()` -> `supabase.auth.signOut()`
- `getCurrentUser()` -> `supabase.auth.getSession()` + profile cache
- `requestPasswordReset()` -> `supabase.auth.resetPasswordForEmail(email)`
- `resetPassword()` -> `supabase.auth.updateUser({ password })` (from reset link callback)
- Remove: `verifyPasswordResetCode()` (Supabase handles via magic link)
- Keep as Netlify function calls: `linkMinecraft`, `unlinkMinecraft`, `updateProfile` (username change needs server-side uniqueness check), `updateRole`, `deleteUser`, `getAllUsers`, `verifyPlayer`, `getLinkedPlayers`, `checkSubscription`, `getTierRewards`, `updateKofiUsername`, `generateKofiLinkToken`, `checkUsernameAvailability`

### 3.2 Rewrite `netlify/functions/auth.ts`
**Remove:** login, register, password reset flows (handled by Supabase Auth SDK)
**Keep & update to Supabase:** All other actions (updateProfile, updateRole, deleteUser, linkMinecraft, unlinkMinecraft, verifyPlayer, getLinkedPlayers, checkSubscription, getTierRewards, updateKofiUsername, generateKofiLinkToken, checkUsername, getAllUsers)
**Auth verification:** Extract JWT from `Authorization: Bearer <token>` header, verify with `supabaseAdmin.auth.getUser(token)`, then check profile role for admin operations.

### 3.3 Update frontend components

| Component | Changes |
|-----------|---------|
| `Login.tsx` | Use email+password (not username). Call `AuthService.login()`. |
| `Register.tsx` | Collect username+email+password. Call `AuthService.register()`. Show email confirmation message. |
| `ForgotPassword.tsx` | Single email input -> "Check email for reset link". Remove 3-step code flow. |
| `Profile.tsx` | Email/password changes via `supabase.auth.updateUser()`. Username changes via Netlify function. |
| `App.tsx` | Add `supabase.auth.onAuthStateChange()` listener. Auto-fetch profile on session. |
| `Navbar.tsx` | Display username from profile (not raw auth user). |
| `AdminPanel.tsx` | Verify admin role from profile. All data fetches use supabase client. |

### 4.3 Key MongoDB-to-Supabase query translations

| MongoDB | Supabase |
|---------|----------|
| `collection.find({}).toArray()` | `.from('table').select('*')` |
| `collection.findOne({ id })` | `.from('table').select('*').eq('id', id).single()` |
| `collection.insertOne(doc)` | `.from('table').insert(doc)` |
| `collection.updateOne({id}, {$set: data})` | `.from('table').update(data).eq('id', id)` |
| `collection.deleteOne({ id })` | `.from('table').delete().eq('id', id)` |
| `collection.find({field: {$regex: /pattern/i}})` | `.from('table').select('*').ilike('field', pattern)` |
| `collection.updateOne({}, {$unset: {field: ""}})` | `.from('table').update({field: null}).eq('id', id)` |
| `collection.bulkWrite(ops)` | `.from('table').upsert(items, {onConflict: 'id'})` |
| `collection.updateOne({}, {$inc: {count: 1}})` | `.rpc('increment_count', {row_id, amount: 1})` or read+update |
| `collection.updateOne({}, {$push: {arr: val}})` | Read array, append, update (or use `array_append` via RPC) |
